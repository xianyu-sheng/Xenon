# v0.8.3 方向思考：学习式验证循环 + 跨轮次状态传递（2026-08-13）

> 目的：论证 v0.8.3 核心改动——把 v0.8.2 的「单轮验证闭环」升级为
> 「学习式多轮验证循环」，其中错误日志累积与正确动作复用是**同一机制
> 的两面**（跨轮次状态传递），必须一体实现。
> 目标：SWE-bench_Lite 45-50% instance-level（当前 v0.8.2 = 40.0%）。
> 版本：v0.8.3（迭代增强，非框架跃迁；框架级变化留给 v0.9）。

---

## 1. 背景与动机

### 1.1 已验证的因果链

v0.8.2 的核心提升来自「验证闭环」：把「写了文件但测试失败且无成功
测试」转成一轮修复执行（失败输出 → 定位断言 → 改代码 → 再验证）。
同模型 A/B（v0.8.0 → v0.8.2，DeepSeek V4 Flash、单次尝试）实证
**+6.7pp instance / +11.0pp cell**。

这证明：**把测试结果反馈给 LLM 是当前框架最有效的单点增益**。
v0.8.2 的局限是只反馈一次——LLM 修完一轮就不再获得新信息，
第二次仍失败就放弃，且没有任何跨轮学习。

### 1.2 v0.8.2 的三个缺口

1. **单轮终止**：修复后不复查，成功与否完全依赖 LLM 自报；
2. **无失败历史**：每轮失败信息覆盖前一轮，LLM 不知道之前试过什么、
   为什么不行 → 重复犯错；
3. **无成功复用**：即使某轮验证通过了部分步骤，下一轮也全部重做
   → 浪费成本，且重做可能引入新错误。

缺口 2、3 是同一问题的两面：**轮次之间没有状态传递**。
v0.8.3 就是把这个状态传递机制做出来。

---

## 2. 核心设计：跨轮次状态传递（学习式多轮）

### 2.1 总览

```
[计划] → [执行] → [测试] ──失败──→ 循环（≤ 上限，动态终止）
                           │            │
                           │      ┌─────┴─────┐
                           │      ▼           ▼
                           │  失败证据      成功证据
                           │  (错误时间线)  (复用缓存)
                           │      │           │
                           └──────┴─────┬─────┘
                                  累积注入下一轮 prompt
```

每轮结束后，`ExecutionEvidence` 捕获的验证结果**按成功/失败分类累积**，
作为下一轮 LLM 的输入。LLM 同时看到：
- **失败时间线**：第 1..N 轮各试过什么、失败原因（避免重复路径）；
- **成功缓存**：哪些步骤已确定性验证通过（直接复用，不再重做）。

这就是「学习」：不是机械重试，而是每轮都站在前一轮的状态上继续。

### 2.2 失败时间线（错误日志累积）

- 每轮把失败测试输出做**结构化摘要**后追加到时间线，而非全文覆盖：
  - 提取「失败类型 + 关键断言/错误行 + 涉及文件/函数」；
  - 第 N 轮 prompt 包含第 1..N-1 轮的全部摘要。
- 防上下文爆炸的分级策略：
  - 最近 3 轮保留原始摘要（LLM 需要细节定位）；
  - 更早轮次压缩为一行级摘要（「R1: AssertionError in test_x」），
    保留「试过什么」的轨迹而不撑爆 prompt。
- 关键：**累积的是「失败轨迹」而非「失败全文」**——目的是让 LLM
  看到收敛方向（错误是否在变化/变少），不是让它重读所有日志。

### 2.3 成功缓存（正确动作复用）——与失败时间线一体实现

复用与错误日志共用同一条数据管道，**不是独立功能**：

1. **捕获**：每轮结束，`ExecutionEvidence` 把验证通过的证据分类标记：
   - 通过的测试命令 → 证据 ID + 输出摘要；
   - 成功写入的文件修改 → 证据 ID + 文件路径 + diff 摘要；
   - 成功的工具调用 → 证据 ID + 参数摘要。
2. **注入**：下一轮 prompt 标注「以下步骤已确定性验证通过，无需重做」，
   带证据 ID 列表；LLM 跳过这些动作，把预算花在未解决部分。
3. **防假复用（关键安全约束）**：
   - 复用必须绑定证据 ID——LLM 声称「已复用」时，框架校验该证据
     是否真实存在且仍有效；
   - 只有**确定性验证通过**的才进缓存；LLM 自述「正确」但不带
     验证证据的一律不缓存（防信任幻觉）；
   - 最终一轮仍强制跑完整验证——复用省的是中间探索，不是最终确认；
     后续改动可能破坏先前通过的部分，最终验证必须覆盖。

### 2.4 轮次预算与动态终止

- **上限 8-10 轮**（3 轮对复杂实例确实不够）；
- **动态提前终止**（防绕圈烧钱）：
  - 无进展检测：连续 2-3 轮失败摘要相同（LLM 在绕圈）→ fail-closed；
  - 收敛检测：失败摘要逐轮变化且在变短（在修复）→ 继续给轮次；
  - 仍受 `max_steps` 总预算约束（双闸门）。
- 每轮注入的失败摘要做**去重**：相同失败不重复追加。

## 3. 与模型侧思考档的关系（正交杠杆）

- `reasoning_effort`（low/medium/high/max）控制单次推理深度，与
  框架侧迭代策略正交：每轮修复质量更高（模型侧）× 轮数更多且
  有学习（框架侧）= 联合增益。
- 当前代码已默认 `deepseek-v4-pro → reasoning_effort=max`
  （`model_registry.py:112`）；flash 未设档。v0.8.3 实验 B 组对
  flash 开 max 验证独立收益。
- 官方 V4 集成指南对 Pro 推荐 max 思考，与框架改动无冲突。

## 4. 预期收益与成本边界

### 4.1 收益估算（保守口径）

| 来源 | 机制 | 预期 |
|------|------|------|
| 失败时间线 | 避免重复错误路径，硬实例多轮收敛 | +2-4pp |
| 成功复用 | 省下重做已验证步骤的成本 → 预算投给未解决部分 | +2-3pp |
| 两者一体 | 每轮站在前轮状态上继续（真正的学习） | **+3-5pp** |
| max 档（flash） | 每轮修复质量更高 | +1-3pp |
| 叠加 | 正交杠杆联合 | **45-50%**（目标） |

### 4.2 成本边界

- 多轮 token 膨胀：上限 8-10 轮 + 动态终止 + 摘要分级累积，
  单实例成本上限 ≈ 当前 ×3-5（当前 < ¥0.1/实例，flash，仍可接受）；
- 成功复用**抵消**部分膨胀：已验证步骤不重做 = 每轮实际新增
  成本下降，复杂任务越到后面越便宜；
- 纯读任务/无失败测试任务零成本（沿用 v0.8.2 触发条件）。

## 5. 实验设计（唯一变量原则）

沿用 v0.8.2 评测纪律（串行、同模型同参数唯一变量、成功复用失败重跑）：

1. **A 组：跨轮次状态传递**（框架侧唯一变量）
   - 基线：v0.8.2 配置（单轮闭环）
   - 实验：学习式多轮（失败时间线 + 成功缓存一体，上限 8-10，
     动态终止）
   - 模型固定：flash 同档位；seed 同 20260729；`--max-steps 10`
2. **B 组：flash max 思考档**（模型侧唯一变量）
   - 基线：A 组基线（flash 未设档）
   - 实验：flash `reasoning_effort=max`，框架配置不变
3. **C 组：联合**（两杠杆叠加）
4. **判定标准**：instance-level resolved 数提升 ≥ 2（≈ +6.7pp 量级）
   才合入；否则回退并记录原因。

### 5.1 实施步骤

1. 重构 `_ensure_verification_loop`（`plan_execute_engine.py:561`）：
   - 单轮 → while 循环，每轮重新捕获 `ExecutionEvidence`；
   - 失败证据结构化摘要 → 时间线累积；
   - 成功证据 → 缓存 + 证据 ID 注入；
   - `verification_max_rounds`（默认 8-10）+ 动态终止（无进展/收敛）。
2. 单测用例：
   - 「补救后仍失败 → 第二轮补救且看到第一轮失败摘要」；
   - 「第二轮成功后 → 立即退出」；
   - 「成功证据注入后 → LLM 跳过已验证步骤」；
   - 「LLM 声称复用但不带证据 ID → 拒绝」；
   - 「预算耗尽 → fail-closed」；
   - 「无进展 2-3 轮 → 提前终止」。
3. 门禁：pytest（2110+）+ ruff + compileall + 本地安装验证。
4. 5 引擎 × 30 实例串行评测（同 v0.8.2 流程），官方 harness grading。
5. 结果落盘 `evals/results/`，A/B/C 三组对比入库。
6. 通过则 bump 0.8.2 → **0.8.3**，双远端 + release + CI。

## 6. 风险与回退

| 风险 | 应对 |
|------|------|
| 多轮不提升（硬实例修不动） | 回退 `verification_max_rounds=1`（= v0.8.2 行为），保留配置项与失败模式记录 |
| 失败时间线撑爆 prompt | 分级摘要（最近 3 轮原始 + 更早一行级）；上限 8-10 轮 |
| 假复用（LLM 声称已做实际没做） | 复用绑定证据 ID，框架校验存在性；最终轮强制完整验证 |
| 复用缓存被后续改动破坏 | 缓存只对「最近一次验证通过」生效，非永久；最终验证全覆盖 |
| max 档成本超限 | 只对评测档开，默认配置不动；或用 high 档替代 |
| 与 mid-task steering 冲突 | 循环内不消费 steering（补救步骤是框架注入，非用户指令） |

---

## 7. 一句话结论

**v0.8.3 = 把 v0.8.2 的单轮验证闭环升级为「学习式多轮验证循环」：
失败时间线 + 成功缓存一体实现（跨轮次状态传递），叠加 flash max
思考档，冲击 45-50%。失败信息与成功证据是同一管道两面，拆开做
等于半套学习。若多轮增益不达阈值，保留配置项回退，不破坏
v0.8.2 已实证的 40.0%。**
