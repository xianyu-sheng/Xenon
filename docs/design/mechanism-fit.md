# 旧机制适配性审计（不是"能不能搬"，是"搬了还对不对"）

对象：拆除期被删掉的机制 + 尚未回迁的遗留项。
问题：这些机制在**单 loop + 事件溯源 + evidence-first** 的设计里，前提还成立吗？迁进来是让 Xenon 更强，还是只是把旧复杂度搬了个家？
日期：2026-10-31

## 判定口径

- **迁入**：前提成立、实现方式与新设计不冲突，直接补。
- **改造后迁入**：需求成立但旧实现形态与今天的设计冲突，必须换一种实现。
- **放弃**：前提在今天不成立，或与新设计的硬约束冲突。**放弃要写理由，不能默默消失。**
- **暂缓**：价值明确，但要先解决结构性冲突（写清冲突是什么）。

## 先看一个反例：多引擎本身就不成立

7 个引擎的隐含前提是"不同任务需要不同的循环结构"。实际上它们的差别只有三件事：要不要先出计划、每步要不要独立预算、收尾前要不要反思——**是数据，不是类型**。把它做成 7 个类，导致：提示词 5 套、builder 5 个、测试 94 个文件、行为无法统一验证。所以合并成一个 `LoopStrategy` + `LoopProfile` 不是"重构"，是**去掉了一个错误抽象**。

这条反例给出了判据：**机制的价值 = 它解决的真实约束**，不是它在旧代码里存在。

## 逐条

| 机制 | 旧前提 | 今天是否成立 | 判定 | 为什么（增量/冲突） |
|---|---|---|---|---|
| 非 LLM 结构化压缩 | 上下文会爆；压缩不能调模型 | **成立** | 改造后已迁入（#323） | 上下文爆炸是物理约束，与架构无关。改造点：旧实现按"工具块"切分，新设计只有事件，因此按事件折叠成摘要 |
| 压缩的粒度 | 每个工具块一行摘要 | **不成立** | 暂缓（见下） | "每个事件一行"在长任务里仍是噪音。真正有用的是**按主题聚合**（同一文件的最新状态、最近一次测试结果），那是"状态视图"而不是"事件摘要"。需要先想清楚主题键，硬做会造出第二套真相 |
| 截断消费 | 引擎要修复被截断的 JSON | **部分成立** | 改造后迁入（本轮） | 续写/标注已在 `llm_client` 里做完，kernel 需要的是把"截断"变成**具体的下一步**，而不是泛化 parse error 后盲目重试 |
| context_window 感知 | 用模型真实窗口决定何时压缩 | **成立，且今天更必要** | 迁入（本轮） | 多模型窗口从 8k 到 200k，`max_tokens*2` 这个魔法系数在两边都错：小窗口溢出、大窗口浪费 |
| 重复调用检测（旧：文本哈希相似度） | 模型打转时，看输出像不像 | **前提不成立** | 改造后已迁入（#323） | "像不像"是启发式，会误杀；改成确定性签名 `(tool, args)`，可解释、可复现 |
| steering（运行中注入用户指令） | 引擎自带 listener 线程，out-of-band 回调 | **需求成立，形态不成立** | 改造后迁入（下一轮） | 线程 + 回调 + 非事件溯源，与"ledger 是唯一真相"直接冲突。正确形态：用户输入作为 `USER_INPUT` 事件落账，下一轮进 view |
| deadline 降级 | 超时后降级继续，尽量给点结果 | **不成立** | **放弃** | 降级 = 降低验证强度 = 可能交付未验证结果，与 evidence-first 正面冲突。今天的选择是预算耗尽 → `BLOCKED` + 债务，由用户决定 |
| DAG 并行执行 | 独立步骤要并行跑，省时间 | **价值成立，结构冲突** | 暂缓 | kernel 是单写者、确定性顺序；并行需要"批量派发 + 确定性排序落账"，否则账本顺序随调度抖动。要先设计 batch 语义 |
| provider 请求事件 | event_bus 广播给 UI | **形态不成立，需求成立** | 改造后迁入（#320） | event_bus 已删；可直接走 kernel 既有的 notices → sink 通道，不需要复活总线 |
| 缓存前缀稳定 | 稳定前缀才能命中 prompt cache | **成立** | 已隐含成立 | system prompt 是确定性生成的、working set 按 seq 排序，前缀天然稳定；不额外加机制，只需**不为它引入随机性** |
| 反思打分（`pass_threshold` / `score`） | 用分数判断"够不够好" | **不成立** | 放弃（已放弃） | 分数是模型自评，不是证据；会让"未验证"通过伪装成"已验证" |
| LLM 驱动的范式自动切换 | 让模型自己选引擎 | **不成立** | 放弃（已删） | 模式是用户/配置的决定，不是模型的决定；自动切换让行为不可复现 |

## 本轮的实现范围

1. **context_window 进入预算**：`Budget.context_window`（0 = 未知，回退启发式）。view 按 `window - 输出预算` 折算输入字符上限，而不是 `max_tokens*2`。
2. **截断变成具体下一步**：模型输出被截断时，在视图的 `notes` 里写明"上一轮输出被截断，请给出更短的 action"，而不是让策略盲重试。

两条都不引入新的抽象层：一个字段 + 一个 notes 通道。

## 不在本轮

- 压缩按主题聚合（要先把"主题键"定清楚，否则会和 claim/evidence 打架）；
- steering（要设计 `USER_INPUT` 在视图里的位置与优先级）；
- DAG 并行（要先有 batch 语义）。

## 复审补充：本轮又找出的遗漏（2026-10-31 第二轮）

按同样的判据（前提是否成立、迁了是否更强）再审一遍，发现 6 处此前没列的东西：

| 遗漏 | 现状 | 判定 | 说明 |
|---|---|---|---|
| **token 用量不计账** | kernel 从不读 `usage`；`Budget.max_tokens` 只用来算视图大小，从不被消耗 | **必须补** | 现在"预算"这个词是假的：任务跑 50 万 token 也不会触发任何东西。补上后才谈得上"预算耗尽 → BLOCKED"，也才有每任务的成本可见性 |
| 上下文窗口只在 REPL 计量 | 本轮修好：模型窗口贯通到 `Budget.context_window`，状态栏显示真实窗口 | 已补 | 之前 kernel 用 `max_tokens*2`、REPL 硬编码 128k，两个都错 |
| **取消打不断模型调用** | `request_cancel()` 只在轮次之间检查 | 待补 | 用户按 Esc 后要等当前模型调用返回（最长几十秒）。真中断需要在 `_call_model` 外层接 cancel 令牌 + httpx 超时收敛 |
| **kernel 路径无流式** | `harness/llm` 只调阻塞式 `chat_completion` | 待补 | 长任务里用户看不到"正在生成"，只能等 |
| **无模型链 fallback** | 旧 `_call_llm` 有"主模型 429/5xx → 下一个模型" | 改造后再说 | 有价值，但静默换模型会破坏可复现性。正确形态：`model_failed` 事件 + 视图里显式写出当前模型 |
| `xenon replay` / 指标 CLI 仍缺 | 账本可读，但没有回放/指标入口 | 待补（#289） | 事件溯源的价值有一半在回放上 |

四条待补里，**token 用量计账**是最要紧的：它同时是"预算真实生效"和"成本可见"的前提，而且完全确定性、不需要真实模型就能测（用回执里的 usage 字段即可）。
