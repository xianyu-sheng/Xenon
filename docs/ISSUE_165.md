# Issue #165：简单查询/报告文档冗杂

## 结论

天气报告被当成“项目/API 技术文档”，不是模型随机啰嗦。

修复前（确定性复现）：

```text
查询一下天气，生成天气文档保存下来
→ intent=write_doc
→ 技术文档模板：概述 / 安装前置 / 用法参数返回值 / 注意事项
→ 策略允许 list_files → search_files → read_file
→ 写 WEATHER_GUIDE.md 触发“代码改动未验证”提醒
```

## 修复

- 新增 `write_report` 意图，优先于通用 `write_doc`：
  外部数据/主题 + 文档/报告 → 数据报告，不再套技术文档模板。
- 报告模板只要求：标题、核心数据/结论、来源与时间、简短建议；
  明确禁止安装步骤、API 参数、返回值、代码实现或仓库结构。
- `write_report` 策略只给查询/读写数据所需工具，不主动探索仓库代码。
- 报告/数据文档写入不触发“必须跑代码测试”的验证提醒；
  若同一轮也写了代码，仍会触发。
- 报告收尾只要求报告路径 + 2–3 条关键结论 + 时间/来源。

## 真实验证（deepseek-v4-flash）

| 项 | 修复前 | 修复后 |
|---|---|---|
| 意图 | `write_doc` | `write_report` |
| 文档模板 | 安装/参数/返回值 | 数据/结论/来源 |
| 文档内容 | 项目/工具说明混杂 | 556 字符天气报告，无安装/参数/代码块 |
| 最终回答 | 大段验证/实现说明 | 219 字符：路径 + 要点 + 时间来源 |
| 文档验证提醒 | 触发 | 不触发（报告写入被识别为非代码） |
