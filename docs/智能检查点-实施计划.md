# 智能检查点机制 - 分阶段实施计划

## 背景

当前多模型路由在模型失败切换时，会丢弃已生成的部分内容，从头开始调用新模型。
这导致了成本浪费、时间浪费和用户体验下降。

## 目标

实现智能检查点机制，在模型切换时保留已生成内容，并从语义边界续写。

---

## Phase 1: 基础设施搭建（MVP）

### 1.1 创建异常类和数据结构

**文件**: `xenon/utils/partial_response.py`

```python
@dataclass
class PartialContent:
    """部分生成内容的数据结构"""
    content: str              # 已生成的内容
    tokens_generated: int     # 已生成的 token 数
    model_id: str            # 生成该内容的模型
    timestamp: float         # 生成时间戳
    finish_reason: str | None  # 中断原因

class PartialResponseError(Exception):
    """携带部分生成内容的异常"""
    def __init__(self, partial: PartialContent, original_error: Exception):
        self.partial = partial
        self.original_error = original_error
        super().__init__(f"部分响应: {len(partial.content)} 字符已生成")
```

### 1.2 修改流式输出捕获

**文件**: `xenon/utils/llm_client.py`

- 在 `_call_openai_compat_once` 中累积流式内容
- 在网络错误时抛出 `PartialResponseError`
- 在 `_call_anthropic_once` 中实现相同逻辑

### 1.3 实现基本续写机制

**文件**: `xenon/engine/base.py`

- 在 `_call_llm_once` 中捕获 `PartialResponseError`
- 判断部分内容是否有效（长度阈值）
- 构造续写 messages
- 切换到下一个模型继续生成

### 验收标准
- ✅ 网络中断时保存已生成内容
- ✅ 切换模型时能够续写
- ✅ 至少节省 50% 的重复生成成本

## Phase 2: 语义边界检测

### 2.1 实现边界检测器

**文件**: `xenon/utils/semantic_boundary.py`

```python
class BoundaryDetector:
    """语义边界检测器"""
    
    def find_last_complete_boundary(self, text: str, context_type: str) -> tuple[str, str]:
        """
        找到最后一个完整的语义边界
        
        Returns:
            (完整部分, 不完整部分)
        """
        # 代码块边界
        # 段落边界
        # 句子边界
```

### 2.2 边界类型识别

支持的边界类型：
- **代码块**: 完整的函数/类/代码块结束
- **Markdown**: 完整的标题/列表/代码块
- **段落**: 完整的段落（双换行）
- **句子**: 完整的句子（句号/问号/感叹号）

### 2.3 智能回滚

在续写前，回滚到最近的完整边界：

```python
# 示例
原始内容: "def foo():\n    return"
回滚后: "def foo():"
续写提示: "请继续完成上述函数"
```

### 验收标准
- ✅ 准确识别代码块边界
- ✅ 准确识别段落边界

## Phase 3: 检查点快照机制

### 3.1 实现检查点管理器

**文件**: `xenon/engine/checkpoint_manager.py`

```python
class CheckpointManager:
    """检查点管理器"""
    
    def __init__(self, interval_tokens: int = 500):
        self.checkpoints: list[Checkpoint] = []
        self.interval = interval_tokens
    
    def save_checkpoint(self, content: str, tokens: int):
        """保存检查点"""
        
    def get_last_valid_checkpoint(self) -> Checkpoint | None:
        """获取最后一个有效检查点"""
```

### 3.2 流式生成中的检查点

在流式生成过程中，每 N tokens 保存一次检查点：

```python
accumulated_tokens = 0
for chunk in stream:
    content += chunk
    accumulated_tokens += estimate_tokens(chunk)
    
    if accumulated_tokens >= checkpoint_interval:
        checkpoint_manager.save_checkpoint(content, accumulated_tokens)
```

### 3.3 智能恢复

中断时，恢复到最近的检查点 + 语义边界：

```python
# 1. 获取最后一个检查点
last_checkpoint = checkpoint_manager.get_last_valid_checkpoint()

# 2. 从检查点找语义边界
complete_part, incomplete_part = boundary_detector.find_last_boundary(
    last_checkpoint.content
)

# 3. 续写
continuation_prompt = f"请从以下内容继续：\n{incomplete_part}"
```

### 验收标准
- ✅ 检查点机制稳定运行
- ✅ 恢复逻辑准确
- ✅ 减少无效续写

  enabled: true
  checkpoint_interval_tokens: 500    # 检查点间隔

## Phase 5: 高级特性

### 5.1 多模型协作日志

记录每个部分由哪个模型生成：

```markdown
# 生成日志

## 第一部分 (deepseek/deepseek-chat, 0-1200 字符)
- 开始时间: 2026-08-28 10:30:00
- 生成 tokens: 300
- 状态: 网络中断

## 第二部分 (anthropic/claude-3-5-sonnet, 1200-2400 字符)
- 开始时间: 2026-08-28 10:30:15
- 续写 tokens: 280
- 状态: 完成
```

### 5.2 智能模型选择

根据续写上下文选择最适合的模型：
- 代码续写 → 优先选择代码能力强的模型
- 长文本续写 → 优先选择 context 长度大的模型

### 5.3 失败降级策略

如果续写也失败：
- 尝试更短的续写提示
- 降级到简单的"继续"提示
- 最后降级到完全重新生成

## 风险和缓解

### 风险 1: 续写语义不连贯
**缓解**: 严格的边界检测 + 上下文提示

### 风险 2: 检查点内存开销
**缓解**: 限制检查点数量（保留最近 3-5 个）

### 风险 3: 某些模型不支持续写
**缓解**: 失败降级到完全重新生成
